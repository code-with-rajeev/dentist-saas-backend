# NAMING_CONVENTIONS.md
# Dentist AI SaaS — Naming Conventions
> Every layer. Every file. Every variable. Zero guessing.

---

## Why This Document Exists

Inconsistent naming is the #1 cause of confusion in multi-session AI-assisted development.
If Antigravity writes `get_appointment` in session 1 and `fetch_appointment` in session 2,
you now have two patterns doing the same thing. This document prevents that.

**Rule: When in doubt, look here first.**

## 1. Python Files & Folders

| Type | Convention | Example |
|---|---|---|
| All Python files | `snake_case` | `appointment_service.py` |
| All folders | `snake_case` | `app/services/` |
| Test files | `test_` prefix + module name | `test_appointment_service.py` |
| Migration files | Auto-generated by Alembic | `0001_create_users_table.py` |

```
✅  appointment_service.py
✅  clinic_repository.py
✅  test_auth.py

❌  AppointmentService.py
❌  clinicRepository.py
❌  Auth_Test.py
```

## 2. Python Classes

| Type | Convention | Example |
|---|---|---|
| All classes | `PascalCase` | `AppointmentService` |
| Pydantic schemas | `PascalCase` + suffix | `AppointmentCreate`, `AppointmentResponse` |

## 3. Functions & Methods

| Type | Convention | Pattern |
|---|---|---|
| All functions | `snake_case` | `get_appointment_by_id` |
| Async functions | same — just add `async` | `async def get_appointment_by_id` |
| Route handlers | verb + noun | `list_appointments`, `create_appointment` |
| Service methods | verb + noun | `confirm_appointment`, `submit_consultation` |
| Repository methods | verb + noun | `get_by_id`, `get_all_by_clinic` |
| Boolean returns | `is_` or `has_` or `can_` prefix | `is_submitted`, `has_permission` |
| Private methods | single underscore prefix | `_calculate_queue_position` |

### Verb Standards — Use These Exactly

**Repository layer verbs:**
```
get_by_id()                 → fetch single by primary key
get_by_{field}()            → fetch single by specific field
get_all_by_clinic()         → fetch list, always clinic-scoped
get_all_by_{field}()        → fetch list filtered by field
create()                    → insert new record
update()                    → update existing record
soft_delete()               → set deleted_at
exists_by_{field}()         → boolean existence check
count_by_{field}()          → integer count
```

**Service layer verbs:**
```
get_{resource}()            → fetch + validate + return
list_{resources}()          → fetch list with filters
create_{resource}()         → validate + create + return
update_{resource}()         → validate + update + return
delete_{resource}()         → validate + soft delete
confirm_{resource}()        → status change: pending → waiting
cancel_{resource}()         → status change: → cancelled
complete_{resource}()       → status change: → completed
submit_{resource}()         → lock and finalize
generate_{output}()         → produce a file/report
```

**Route handler verbs:**
```
list_{resources}()          → GET collection
get_{resource}()            → GET single
create_{resource}()         → POST
update_{resource}()         → PATCH
delete_{resource}()         → DELETE
confirm_{resource}()        → PATCH status action
cancel_{resource}()         → PATCH status action
complete_{resource}()       → PATCH status action
submit_{resource}()         → POST action
download_{resource}()       → GET file
```

```
✅  async def get_appointment_by_id(appointment_id, clinic_id)
✅  async def list_appointments(filters, clinic_id)
✅  async def confirm_appointment(appointment_id, clinic_id)

❌  async def fetchAppointment(id)
❌  async def appointment_getter(appt_id)
❌  async def handle_appointment_confirm(...)
```

## 4. Variables & Parameters

| Type | Convention | Example |
|---|---|---|
| All variables | `snake_case` | `clinic_id`, `appointment_status` |
| Constants | `UPPER_SNAKE_CASE` | `MAX_QUEUE_SIZE`, `JWT_ALGORITHM` |
| Boolean variables | `is_`, `has_`, `can_` prefix | `is_active`, `has_permission` |
| ID parameters | `{resource}_id` | `patient_id`, `clinic_id`, `appointment_id` |
| Loop variables | descriptive, not `i` or `x` | `for appointment in appointments` |
| Query result (single) | singular noun | `patient`, `appointment` |
| Query result (list) | plural noun | `patients`, `appointments` |

```
✅  patient_id, clinic_id, appointment_id
✅  is_active, is_submitted, has_permission
✅  MAX_QUEUE_SIZE = 100

❌  patientId, clinicID, appt_id
❌  active, submitted, permission_check
❌  max_queue_size = 100   ← constant should be UPPER_SNAKE_CASE
```

## 5. Pydantic Schema Naming

Schemas live in `app/schemas/{module}.py`. Every resource has a consistent set.

| Schema | Purpose | Example |
|---|---|---|
| `{Resource}Create` | POST request body | `AppointmentCreate` |
| `{Resource}Update` | PATCH request body (all fields optional) | `AppointmentUpdate` |
| `{Resource}Response` | Single resource response | `AppointmentResponse` |
| `{Resource}ListResponse` | Paginated list response | `AppointmentListResponse` |
| `{Resource}StatusUpdate` | Status-change request body | `AppointmentStatusUpdate` |
| `{Resource}Filter` | Query param filters for list endpoints | `AppointmentFilter` |

```
✅  AppointmentCreate
✅  AppointmentUpdate
✅  AppointmentResponse
✅  AppointmentListResponse

❌  AppointmentSchema
❌  CreateAppointmentRequest
❌  AppointmentOut
❌  AppointmentDTO
```

## 6. SQLAlchemy Model Naming

Models live in `app/models/{module}.py`.

| Type | Convention | Example |
|---|---|---|
| Model class | `PascalCase` singular | `Appointment`, `ClinicMember` |
| Table name | `snake_case` plural | `appointments`, `clinic_members` |
| Primary key | always `id` | `id: UUID` |
| Foreign keys | `{referenced_table_singular}_id` | `clinic_id`, `patient_id`, `dentist_id` |
| Boolean columns | `is_` prefix | `is_active`, `is_submitted` |
| Timestamp columns | `_at` suffix | `created_at`, `deleted_at`, `submitted_at` |
| Enum columns | descriptive noun | `status`, `role`, `appointment_type` |

```
✅  class Appointment → __tablename__ = "appointments"
✅  class ClinicMember → __tablename__ = "clinic_members"
✅  clinic_id, patient_id, created_by
✅  is_active, is_submitted
✅  created_at, updated_at, deleted_at

❌  class AppointmentModel
❌  __tablename__ = "Appointment"
❌  clinicId, patientID
❌  active, submitted
❌  createdAt, created_date
```

## 7. API Route Naming

| Rule | Convention | Example |
|---|---|---|
| Base path | `/api/v1/` | `/api/v1/appointments` |
| Resource names | `kebab-case`, plural nouns | `/appointments`, `/clinic-members` |
| Path parameters | `snake_case` | `/{appointment_id}` |
| Action endpoints | `/resource/{id}/action` | `/appointments/{id}/confirm` |
| Nested resources | `/parent/{id}/child` | `/patients/{id}/consultations` |
| No verbs in URL | noun only | `/appointments` not `/get-appointments` |
| No trailing slash | clean URLs | `/appointments` not `/appointments/` |

```
✅  GET    /api/v1/appointments
✅  POST   /api/v1/appointments
✅  GET    /api/v1/appointments/{appointment_id}
✅  PATCH  /api/v1/appointments/{appointment_id}/confirm
✅  GET    /api/v1/patients/{patient_id}/consultations

❌  GET    /api/v1/getAppointments
❌  POST   /api/v1/appointment
❌  PATCH  /api/v1/appointments/{id}/doConfirm
❌  GET    /api/v1/patients/{patientId}/consultations
```

## 8. Database Naming

| Type | Convention | Example |
|---|---|---|
| Table names | `snake_case`, plural | `appointments`, `clinic_members` |
| Column names | `snake_case` | `scheduled_date`, `is_active` |
| Primary key | always `id` | `id UUID PRIMARY KEY` |
| Foreign keys | `{table_singular}_id` | `clinic_id`, `patient_id` |
| Index names | `idx_{table}_{column(s)}` | `idx_appointments_clinic_date` |
| Unique index names | `uq_{table}_{column(s)}` | `uq_users_email` |
| Enum type names | `{context}_type` or `{context}_status` | `appointment_status`, `member_role` |

```
✅  TABLE: appointments        COLUMN: scheduled_date      INDEX: idx_appointments_clinic_date
✅  TABLE: clinic_members      COLUMN: clinic_id           INDEX: uq_clinic_members_user_clinic
✅  ENUM:  appointment_status  VALUES: pending, waiting, cancelled

❌  TABLE: Appointment         COLUMN: scheduledDate       INDEX: appointment_index_1
❌  TABLE: clinic_member       COLUMN: clinicId
❌  ENUM:  AppointmentStatus   VALUES: Pending, Waiting
```

## 10. Constants & Enums

### Python Enums (in `app/constants/`)

```python
# ✅ Correct
class AppointmentStatus(str, Enum):
    PENDING   = "pending"
    WAITING   = "waiting"
    CANCELLED = "cancelled"
    NO_SHOW   = "no_show"
    COMPLETED = "completed"

# ✅ Correct
class MemberRole(str, Enum):
    CLINIC_OWNER  = "clinic_owner"
    ASSISTANT     = "assistant"
    RECEPTIONIST  = "receptionist"
    HELPER        = "helper"
    COMPOUNDER    = "compounder"
    OTHER         = "other"

# ❌ Wrong
class appointment_status(Enum):
    pending = 1
    waiting = 2
```

### Module-level Constants

```python
# ✅ Correct — UPPER_SNAKE_CASE
MAX_QUEUE_SIZE          = 50
DEFAULT_PAGE_SIZE       = 20
MAX_PAGE_SIZE           = 100
PATIENT_CODE_PREFIX     = "PAT"
APPOINTMENT_CODE_PREFIX = "APT"
JWT_ALGORITHM           = "HS256"

# ❌ Wrong
maxQueueSize = 50
default_page_size = 20
```

## 11. Test Naming

| Type | Convention | Example |
|---|---|---|
| Test files | `test_` + module | `test_appointment_service.py` |
| Test functions | `test_` + scenario | `test_confirm_appointment_success` |
| Test scenarios | descriptive, outcome-focused | `test_cancel_completed_appointment_raises_error` |
| Fixtures | descriptive noun | `clinic_owner`, `test_patient`, `auth_headers` |
| Test classes | `Test` + subject | `TestAppointmentService` |

```
✅  def test_confirm_appointment_success()
✅  def test_confirm_appointment_already_waiting_raises_error()
✅  def test_patient_not_found_returns_404()

❌  def test_confirm()
❌  def test1()
❌  def testConfirmAppointment()
```

## 12. Git & Commits

### Branch Naming
```
feature/{short-description}     → feature/appointment-queue
fix/{short-description}         → fix/consultation-lock-bug
chore/{short-description}       → chore/add-indexes
migration/{description}         → migration/add-follow-up-table
```

### Commit Messages
```
Format: {type}: {short description}

Types:
  feat     → new feature
  fix      → bug fix
  chore    → tooling, config, deps
  refactor → code restructure, no behavior change
  test     → adding or fixing tests
  docs     → documentation only
  migration→ DB migration

✅  feat: add appointment confirm endpoint
✅  fix: consultation lock not enforced on PATCH
✅  migration: add follow_ups table
✅  chore: update requirements.txt

❌  updated stuff
❌  fixed bug
❌  WIP
```

## 13. Quick Cheat Sheet

```
Files/Folders     → snake_case
Classes           → PascalCase
Functions/Vars    → snake_case
Constants/Enums   → UPPER_SNAKE_CASE
DB Tables         → snake_case plural
DB Columns        → snake_case
API Routes        → kebab-case plural nouns, no verbs
Env Variables     → UPPER_SNAKE_CASE with prefix
Schema suffix     → Create | Update | Response | ListResponse | Filter
Repository verbs  → get_ | get_all_ | create_ | update_ | soft_delete_ | exists_ | count_
Service verbs     → get_ | list_ | create_ | update_ | delete_ | confirm_ | cancel_ | complete_ | submit_ | generate_
Route verbs       → list_ | get_ | create_ | update_ | delete_ | confirm_ | cancel_ | complete_ | submit_ | download_
```
